01
Hardware

Seating the ESP32-S3 on the Expansion Board

The Lonely Binary ESP32-S3 Gold Edition is a dual-row castellated/pin-header module exposing the full GPIO complement of Espressif's ESP32-S3 SoC. Before any wiring begins, the module must be mechanically seated and electrically mated to the Lonely Binary Expansion Board with strict attention to orientation.

Fig 1.1 — ESP32-S3 Gold Edition: top-down view
Fig 1.2 — Expansion Board receptacle sockets

Orientation: Locate the USB-C port on the ESP32-S3 module. The expansion board is silkscreened with a matching USB symbol or notch indicator on one side. These two markers must align — inserting the module backwards will map 3.3 V rails to incorrect pins and can permanently damage both boards. With the module correctly oriented, position it above the two rows of 2.54 mm female receptacles on the expansion board, ensuring every pin is directly above its corresponding socket.

Seating procedure: Apply even downward pressure across both ends of the module simultaneously. Never rock or lever the board from one side, as this bends the inner pins. Press firmly until the plastic pin shoulders sit flush against the receptor housings — you should feel a distinct click as each row seats. Visually inspect all four corners to confirm no pins are misaligned or bridging adjacent sockets.

⚠️
Static Precaution: The ESP32-S3's GPIO matrix and USB PHY are sensitive to electrostatic discharge. Handle the module by its edges and work on an anti-static mat or grounded surface. Touch a grounded metal object before picking up either board.
Fig 1.3 — Fully seated module: flush pin shoulders confirm correct installation

Once seated, the expansion board provides physical strain relief and exposes the ESP32-S3's GPIO rows in clearly labeled breakout headers, a dedicated USB pass-through connector, and power-rail distribution strips. These breakout headers are what we will reference for all subsequent wiring steps.

02
Power Rails

Establishing 3.3 V and Ground on the Breadboard

The ESP32-S3 operates at a native logic level of 3.3 V. All peripherals in this build — including the ST7735 display — are specified for 3.3 V operation. Routing power through the breadboard's distribution rails creates a clean, shared reference for every component and avoids long, impedance-inducing point-to-point wires.

Fig 2.1 — 3.3 V / GND jumpers to breadboard rails

3.3 V rail: Locate the pin labeled 3V3 (or 3.3V) on the expansion board's power header. Run a short red or orange 22 AWG jumper wire from this pin to the positive (+) column of your breadboard. If your breadboard has two independent rail sections (top and bottom), link them with a short bridge jumper so all positive columns carry 3.3 V simultaneously.

Ground rail: Locate any GND pin on the expansion board — there are usually multiple. Run a black jumper wire to the negative (−) column of your breadboard. As with the positive rail, bridge both sections if needed. A solid common ground is critical: without it, voltage level differences between components will cause erratic SPI communication and corrupted display output.

ℹ️
The expansion board's onboard regulator sources 3.3 V directly from the ESP32-S3's internal LDO. The maximum safe draw from this rail when powering external peripherals is approximately 300–500 mA. The ST7735 display draws roughly 40–80 mA during active rendering, well within budget.
03
SPI Bus

5-Wire SPI Connection: ST7735 to ESP32-S3

The 1.8″ ST7735 display communicates over a 4-wire SPI bus plus one dedicated data/command (D/C) control line, totaling five signal wires. The ESP32-S3's hardware SPI peripheral (SPI2 / HSPI) handles the clock generation and data shifting in silicon, freeing the CPU for application logic and delivering reliable timing even at 26 MHz SPI clock speeds.

Fig 3.1 — ST7735 module: SPI pin header detail
Fig 3.2 — Completed 5-wire SPI harness

Use the following reference table for all signal connections. GPIO numbers correspond to the ESP32-S3's logical GPIO index as labeled on the expansion board silkscreen.

Display Pin Signal Function ESP32-S3 GPIO Description
CS Chip Select (Active LOW) GPIO 5 Selects the ST7735 as the active SPI slave. Pull LOW to enable; HIGH to deselect and release the bus.
RESET Hardware Reset (Active LOW) GPIO 4 Drives the controller reset sequence. The Adafruit library pulses this pin LOW for ≥10 ms on begin().
A0 / DC Data / Command Select GPIO 2 HIGH = pixel data byte; LOW = command register byte. This line disambiguates every SPI payload to the ST7735.
SDA / MOSI Master Out Slave In GPIO 23 Serial data line. Pixel color data and register commands are clocked out MSB-first on this line.
SCK SPI Clock GPIO 18 Hardware SPI clock. The ST7735 samples SDA on the rising edge (CPOL=0, CPHA=0, Mode 0).
VCC Supply Voltage 3.3 V Rail Connect to the breadboard's positive 3.3 V rail established in Step 2.
GND Ground GND Rail Connect to the breadboard's ground rail. A shared GND is mandatory for valid SPI voltage levels.
🚫
Do NOT connect the ST7735 to 5 V. The display controller and its glass LCD panel are rated for 3.3 V maximum. Applying 5 V will immediately destroy the ST7735 IC. The ESP32-S3's 3.3 V logic is directly compatible — no level shifting is required in this build.

Verify wire continuity with a multimeter in continuity mode before powering on: probe each signal wire end-to-end, then probe between any VCC/GND node pairs to confirm no accidental shorts exist on the breadboard.

04
Arduino IDE

Software Configuration & Library Installation

Fig 4.1 — Arduino IDE
Fig 4.2 — Core Tech Weather Tracker & GFX

The Arduino IDE (version 2.x recommended) requires Espressif's ESP32 Arduino core before it can target any ESP32-series chip. This core installs the compiler toolchain, linker scripts, board definitions, and hardware abstraction layer (HAL) that translates Arduino API calls into ESP32-S3 machine instructions.

  1. Open Arduino IDE. Navigate to File → Preferences (macOS: Arduino IDE → Settings). In the "Additional boards manager URLs" field, paste the Espressif stable release URL: https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json Click OK.
  2. Open Tools → Board → Boards Manager. Search for esp32. Locate the entry published by Espressif Systems and click Install. This downloads ~250 MB of toolchain and SDK files.
  3. After installation, navigate to Tools → Board → ESP32 Arduino and select ESP32S3 Dev Module. This board definition correctly maps the USB CDC, flash geometry, and PSRAM configuration for the S3.
  4. Configure the following board settings under the Tools menu: USB Mode → USB-OTG (TinyUSB) or USB CDC On Boot → Enabled to activate the native USB serial port for debugging output on the Serial Monitor.
  5. Open Tools → Manage Libraries. Search for Adafruit ST7735 and install Adafruit ST7735 and ST7789 Library. When prompted, select Install All to also install the Adafruit GFX Library dependency, which provides all primitive drawing functions (text, shapes, bitmaps).
  6. In the same Library Manager, search for WiFiManager and install the version by tzapu. This library is the core of the captive-portal credential system described in Section 5.
💡
The ESP32 Arduino core ships with a hardware SPI driver that automatically uses SPI2 (HSPI) when the GPIO pins defined in your sketch match the S3's hardware SPI peripheral mapping. Always pass your CS, DC, and RESET pins to the Adafruit_ST7735 constructor and call tft.initR() with the correct tab-color constant for your specific 1.8″ module (INITR_BLACKTAB is the most common).

Firmware

WiFiManager: Captive Portal & Secure Credential Handling

Fig 5.1 — WiFiManager captive portal on a smartphone browser
Fig 5.2 — Complete SetUP

Hardcoding a Wi-Fi SSID and password directly into firmware is a widespread and serious security antipattern. The credentials are compiled into the binary image, visible to anyone with physical access to the device who can read flash memory with a logic analyzer or esptool.py. They also require a firmware reflash every time the network changes — an impractical constraint in any deployed product. The WiFiManager library by tzapu eliminates both problems through a dynamic captive portal provisioning flow.

How it works: On first boot (or after credential erasure), the ESP32-S3 finds no stored Wi-Fi credentials in its NVS (Non-Volatile Storage) partition. WiFiManager responds by configuring the ESP32-S3's integrated Wi-Fi radio as a soft access point (SoftAP) with a user-defined SSID (in our sketch: "CTech-Setup"). Any Wi-Fi-capable device that connects to this AP is served a DNS redirect that forces all domain queries to resolve to 192.168.4.1 — the hallmark behavior of a captive portal, identical to hotel and airport Wi-Fi login pages.

At that address, a minimal HTTP server presents an HTML configuration page listing all visible SSIDs discovered by the ESP32-S3's active scan, plus password input fields. The user selects their network, enters the passphrase, and submits. WiFiManager stores the credentials in ESP32-S3 NVS flash (encrypted at rest by the ESP-IDF secure storage mechanism), shuts down the SoftAP, and connects to the selected network as a station. On all subsequent boots, autoConnect() reads NVS, attempts the stored credentials, and skips the portal entirely if successful.

🔒
No Hardcoded Secrets
Credentials never appear in source code, compiled binaries, or version control history. The flash-resident NVS partition is separate from the firmware image.
🔄
Zero-Reflash Reconfiguration
Changing networks requires only a portal reset call — no IDE, no USB cable. Call wm.resetSettings() to clear NVS and trigger reprovisioning.
📱
Any-Device Provisioning
The captive portal is a standard web page. Any browser on any OS — phone, tablet, laptop — can provision the device without installing special apps.
⚡
Fast Reconnection
Stored NVS credentials allow the ESP32-S3 to associate with a known AP in under two seconds on warm boot, bypassing the full scan-and-portal cycle.
🖥️
TFT Status Feedback
The configModeCallback in our sketch writes portal SSID and IP directly to the ST7735 display so users always know the device's current state without opening a serial console.
🛠️
Extensible Parameters
WiFiManager's custom parameter API lets you add extra fields (API keys, MQTT broker addresses, device names) to the portal form, persisting all values in NVS alongside Wi-Fi credentials.
